# Аналіз Технічного Завдання проєкту "Student Assistant"

## Функціональні вимоги
На основі переглянутого ТЗ застосунок повинен забезпечувати наступні базові можливості для користувача:
* **Перегляд списку завдань:** відображення всіх поточних та виконаних навчальних тасків.
* **Створення нових завдань:** можливість додавати нове завдання із зазначенням назви, дедлайну та рівня пріоритету.
* **Керування статусом виконання:** швидка зміна стану завдання (виконано / не виконано).
* **Редагування та видалення:** можливість коригувати атрибути існуючих завдань або видаляти застарілі.
* **Фільтрація та сортування:** організація списку завдань за пріоритетом або за станом виконання.

## Нефункціональні вимоги
* **Кросплатформність:** підтримка роботи на операційних системах Windows, macOS та Linux завдяки використанню гетерогенних технологій.
* **Архітектурна незалежність:** кожен модуль розгортається окремо й не має прямих залежностей від інших модулів (спільний лише файл даних).
* **Контроль версій:** ведення розробки строго за Git-моделлю (feature-гілки, Pull Requests, рецензування коду).
* **Зручність інтерфейсу (Usability):** збереження єдиного підходу до взаємодії з даними незалежно від платформи та форми клієнта.

## Формат обміну даними
Усі клієнтські модулі синхронізуються через єдиний локальний JSON-файл `data/tasks.json`.

**Структура об'єкта завдання:**
* `id` (number) — унікальний ідентифікатор завдання;
* `title` (string) — назва завдання;
* `completed` (boolean) — прапорець виконання (`true`/`false`);
* `dueDate` (string) — дата дедлайну у форматі `РРРР-ММ-ДД` (наприклад, `2026-10-15`);
* `priority` (string) — пріоритет із фіксованим набором значень: `"low"`, `"medium"`, `"high"`.

## Відкриті питання
1. **Синхронізація конфліктів запису:** Як має поводитися система, якщо два клієнти одночасно спробують перезаписати файл `data/tasks.json`?
2. **Формат id:** Чи використовуватиметься автоінкремент за порядком, чи генеруватиметься UNIX-timestamp / UUID для гарантії унікальності між клієнтами?
3. **Обробка помилок парсингу:** Яка поведінка очікується від клієнтських модулів у разі пошкодження структури `tasks.json` або відсутності обов'язкових полів?
